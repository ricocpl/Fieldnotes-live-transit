# Optional National Rail connection

The static application works without this service. It does **not** fabricate Heathrow Express departures when this connection is absent. Registration and licensing: https://www.nationalrail.co.uk/developers/darwin-data-feeds/ . Public JSON LDBWS documentation: https://realtime.nationalrail.co.uk/LDBWS/docs/documentation.html and https://realtime.nationalrail.co.uk/LDBWS/static/ldbws.json .

1. Register for the public JSON LDB Webservice (PV) through the Rail Data Marketplace. Confirm the supplied credential format and licence. Do not paste credentials into GitHub, the app or this document.
2. Create a Cloudflare Worker from the dashboard, paste `worker.js`, and use a dedicated hostname. Configure Cloudflare Access for that hostname with a policy restricted to your own approved identity. Disable any alternative public Worker hostname or route that bypasses Access. The Worker validates Access JWT signatures, issuer, audience and expiry itself.
3. Set `ACCESS_ISSUER` (e.g. `https://your-team.cloudflareaccess.com`), `ACCESS_AUD` (the application's audience tag), `FRONTEND_ORIGIN` (e.g. `https://yourname.github.io`, **not** the repository path). Set `DARWIN_AUTHORIZATION` as an encrypted Worker secret containing the complete `Authorization` header specified by your provider (e.g. `Basic …`), not just a raw token. Never expose the value to the client.
4. Configure a Cloudflare rate limiting binding named `RATE_LIMITER` (e.g. 30 requests per 60 seconds per authenticated subject). This is a required binding: the Worker fails closed if absent. Check current account plan availability. If using a dashboard-only deployment and the binding cannot be added there, use Cloudflare's supported configuration workflow; no Node.js is required for the frontend itself.
5. Sign into `https://your-worker-host/health` in Safari. Verify `ok: true` and `darwinConfigured: true`. In the app's Settings, enter the HTTPS Worker base URL, save, and open a Heathrow Express station.
6. Verify CORS and Access preflight handling; configure Access to allow legitimate OPTIONS preflight while still requiring auth for GET. iOS Safari may block cross-site cookies; use sibling HTTPS custom domains on the same registrable domain (GitHub Pages custom domain + Worker custom domain) if required. Do not weaken the Access policy to bypass cookie restrictions. The proxy only accepts PAD, HXX, HWV, uses a fixed upstream and filters HX services. Test unauthenticated requests, invalid CRS, forbidden origin, rate limits and real board results before relying on it.

The official Swagger spec lists `GetDepBoardWithDetails/{crs}` and `Authorization: Basic …`. Upstream deployment/credentials have not been tested here. If the provider changes its endpoint, update the fixed Worker URL after verifying official documentation. Verify the row limits with your subscription; reduce numRows if needed (reducing rows can hide Heathrow Express services at Paddington). No public CORS relay is used.

## Web Push
The service worker has push/click handlers only; subscription management, VAPID keys, a remote scheduler and delivery backend are **not implemented**. The application clearly labels this. Do not enable background alerts without a separate authenticated delivery service, consent, expiry and unsubscribe support. iPhone Safari requires compatible installed Home Screen web apps for Web Push. Foreground alerts operate independently.
